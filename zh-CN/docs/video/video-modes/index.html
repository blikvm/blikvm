视频模式

BliKVM 采集被控电脑的 HDMI 画面，再传输到浏览器。编码格式（H.264、H.265 或 JPEG）与传输方式（WebRTC 或 HTTP）解决的是不同环节的问题。可用组合取决于设备、固件和浏览器，请以实机提供的选项为准。

选择模式并验证​

进入设置 → 视频与摄像头 → HDMI 视频 → 高级设置，修改前先记住当前模式。

Demo 截图：模拟设置不代表某款实机已经支持相应编码或达到某个性能指标。

  1. 若提供 H.264 WebRTC，可以先尝试该模式。
  2. 等待画面重新连接，同时检查动态内容和静态文字。
  3. 连接失败时先切回原模式。若提供 MJPEG，可以用它辅助区分 HDMI 采集故障和视频传输故障。
  4. 使用画质选项调整编码质量配置。当前默认配置的采集和编码分辨率跟随输入信号，输出帧率跟随输入时序，画质控制编码码率档位；不要将旧版手动 GOP、分辨率和帧率选项套用到新版。每次只改一项，再对比响应和清晰度。
模式适合何时尝试条件与取舍
H.264 WebRTC一般远程控制。浏览器支持相应编码，且 WebRTC 媒体连接可达，见 WebRTC 排查。
H.265 WebRTC设备和浏览器均支持 H.265 时。支持情况受浏览器、操作系统和解码器影响，另一台电脑可用不代表当前环境也可用。
MJPEG兼容性排查或回退。通过 HTTP(S) 传输独立 JPEG 帧，通常更占带宽，该图像流不携带音频。

带宽不足时，降低码率可能有帮助；提高码率无法解决丢包或媒体端点不可达。不能仅根据硬件型号，套用旧软件时代的视频模式结论。

远程访问时注意什么​

通过代理或隧道打开网页，不代表 WebRTC 媒体连接已经连通。WebRTC 会协商独立的媒体连接；应先在局域网验证，再用同一模式测试远程连接。当前版本不再提供旧版 QUIC/MoQ 模式。

截图与录制​

  • 点击工具栏的截图保存一帧画面，下载后检查图片内容。
  • 当前 WebRTC 播放器和浏览器支持时，从工具栏开始录制，完成操作后停止，浏览器会下载 WebM 文件。保存完成前保持页面打开。MJPEG 模式不提供该录制按钮。
  • 录制取决于当前播放器和浏览器能力，不能默认每种模式均支持，也不能默认一定包含声音。正式录制前先做一段短测试并回放。

常见问题​

现象处理方向
所有模式均无信号先检查电脑电源、HDMI 接线方向及输入分辨率。
MJPEG 有画面，WebRTC 失败检查 ICE / 媒体网络连接和浏览器编码支持。
卡顿或画面模糊先在局域网对比，降低负载或画质档位，再排查远程网络。
有画面但无法输入检查 USB 和输入权限；切换编码不能修复 USB 连接。
