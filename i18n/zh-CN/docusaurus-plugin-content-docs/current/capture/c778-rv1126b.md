# C778 接入 RV1126B

本指南以 **Luckfox Aura / RV1126B** 的 LT6911UXE 接入配置为起点。其他 RV1126B 主板需要重新核对 CSI、I²C、供电、GPIO 与音频线序，不能直接复用引脚号。

:::warning 适配示例，尚未完成 C778 整板验收
当前构建资料包含 LT6911UXE profile，但板侧 GPIO、时钟和接线仍有待确认。本预览不承诺 Pi 5 双路半幅固件能够直接运行在 RV1126B 的单 CSI 路径上，也不提供未经验证的系统刷写指令。
:::

## 与 Pi 5 方案的区别

| 项目 | Pi 5 当前厂测方案 | RV1126B 当前配置示例 |
| --- | --- | --- |
| CSI 路径 | 两条并行半幅路径 | 一条四 Lane CSI0 路径 |
| 像素数据 | BGR888_1X24，视频队列 RGB3 | 驱动按芯片输出识别 RGB/YUV；需核对实际协商格式 |
| 软件 | LT 桥接驱动 + RP1-CFE + DTBO | Rockchip BSP 媒体驱动 + 板级 DTS |
| 模式依据 | 960×1080 @ 120 × 2 的厂测合同 | 需用匹配的单路固件补齐实测模式表 |

单 CSI 接入若仍使用左右拆分固件，可能只得到半幅画面。应先由固件版本与模式表明确完整画面如何输出，再进行主机适配。

## 板级配置需要对齐的内容

现有 Aura 示例使用以下配置，它们是**适配依据，不是任意主板的通用接线表**：

- I²C4，Linux 7-bit 地址 `0x2b`。厂家文档中的 8-bit `0x56` 不应直接填进 Linux 设备树。
- `compatible = "lontium,lt6911uxe"`，四条 data Lane `<1 2 3 4>`。
- 提供 24 MHz `xvclk` 的设备树描述；该描述与 C778 实际板载时钟的对应关系需复核。
- CSI endpoint 成对连接到板级接收端，关闭占用同一路径的其他桥接节点。
- reset、power、plugin-detect GPIO 在示例中暂未绑定，不能据此推断 C778 不需要复位/检测。
- I²S 使用独立音频路径；现有示例为 SAI2 M1，按实际 C778 与 Aura 接口核对。

## 驱动集成顺序

1. 锁定目标板与 BSP/内核版本，保留当前可恢复镜像。
2. 整理 BSP 中的 `drivers/media/i2c/lt6911uxe.c`、Kconfig/Makefile 和相关接收端补丁。
3. 对照 C778 引脚表调整 DTS 的 I²C、CSI endpoint、Lane、时钟与 GPIO。
4. 将芯片固件、媒体总线格式和主机采集格式匹配。RGB 与 YUV 的解释不一致可能导致偏色、步长错误或无图。
5. 依照目标 BSP 的原有构建流程生成并审核 DTB、内核模块/镜像；使用经过验证的恢复/刷写步骤部署。
6. 从低负载、已确认输入模式开始采集，再逐步测试目标分辨率、帧率与音频。

已在构建机中定位到 Rockchip 的 LT6911UXE V4L2 媒体驱动（文件标注 GPL-2.0）。它与厂家提供的固件升级示例用途不同；源码时序表中存在某种分辨率，不代表 C778 整板已经通过相应模式的验收。

厂家固件升级示例不包含完整的 Linux 媒体采集链路。正式驱动仓库将区分视频驱动、板级适配和芯片固件维护，避免安装驱动时自动刷写不匹配的固件。

## 在已适配系统上检查

以下命令用于收集信息，不会烧写固件：

```bash
uname -a
cat /proc/device-tree/model
v4l2-ctl --list-devices
for media in /dev/media*; do
  [ -e "$media" ] || continue
  media-ctl -d "$media" -p
done
dmesg | grep -Ei 'lt6911|csi|rkcif|dphy|i2c'
```

从拓扑确认实际 capture 节点后，将下面的路径替换成该节点：

```bash
# /dev/videoX 是占位符，不能直接照抄
v4l2-ctl -d /dev/videoX --all
v4l2-ctl -d /dev/videoX --list-formats-ext
```

确认格式、分辨率和完整画面正确后，再在已配置链路上做短时取流：

```bash
# 只验证当前已协商配置，不自动配置 pad / 输入时序
v4l2-ctl -d /dev/videoX --stream-mmap=4 --stream-count=120 --stream-to=/dev/null
```

若系统未包含上述工具，应在 BSP rootfs 阶段加入 `v4l-utils`；不要假设 Buildroot 系统提供 `apt`。MC-centric 媒体设备可能必须先配置 media graph 才能取流，见 [Linux 媒体设备说明](https://www.kernel.org/doc/html/latest/userspace-api/media/v4l/open.html)。

## 音频与最终验收

音频另行核对 C778 的 SDOUT、WS、SCLK、可选 MCLK、主机输入引脚与电平。已有声卡节点不等于音频数据正确；需要录音并检查采样率、左右声道、时钟和连续性。

正式支持列表应列出**主板、系统、内核、驱动、DTS、芯片固件、输入时序、采集格式/帧率和音频结果**。在实物验证完成前，RV1126B 保持“适配中”。
