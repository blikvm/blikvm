# 反向代理

反向代理可提供域名和证书，将 HTTPS 请求转发给 BliKVM。它主要处理网页、API 和信令；WebRTC 媒体仍需要独立可达的 ICE 通路。

## 部署检查表

1. 先确认代理服务器可以访问设备的 HTTPS 地址。
2. 配置域名与证书，保留原始 Host / 转发信息，并支持 WebSocket 升级。
3. 对长连接设置合适的超时；虚拟介质与升级包上传还需匹配上传大小限制。
4. 使用能够校验上游证书的部署方式。不要将关闭设备认证作为解决代理错误的办法。
5. 分别测试网页、登录、WebRTC、终端和必要的文件上传。

当前原生信令包含 WebSocket 路径，不能仅按旧版普通页面配置代理。不同代理软件语法不同，代理方应根据实际端口、证书和转发拓扑编写配置。

## 常见故障

| 现象 | 重点检查 |
| --- | --- |
| 静态页面可见但无法登录 | Cookie、同源信息、HTTPS 及认证请求是否正常转发 |
| 视频一直连接中 | WebSocket 信令及独立媒体通路，见 [WebRTC](../../video/webrtc.md) |
| 上传中断 | 代理的请求体大小、缓冲和超时限制 |
| IP 规则识别异常 | 代理与设备的实际来源地址；不要假设所有转发头都受信任 |

若使用固定端口媒体通路，HTTPS 可以由代理提供，UDP 仍需按[端口转发](./port-forwarding.md)单独部署。用 VPN 访问时，则检查 VPN 地址与路由。
