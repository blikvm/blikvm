# 音频与麦克风

音频存在不同方向，不应只用“双向语音”概括所有连接。可用性取决于硬件、当前模式、USB 类别和账号权限。

| 方向 | 入口 / 前置条件 | 验证方式 |
| --- | --- | --- |
| 被控电脑 → 浏览器 | 可采集的电脑音频、支持音频的 WebRTC 连接，工具栏音量控制；需要收听权限 | 电脑播放测试音，浏览器能听见 |
| 管理电脑麦克风 → 被控电脑 | 工具栏麦克风、浏览器授权及发送音频权限；电脑侧需启用 USB 麦克风类别 | 电脑选择相应输入设备，在录音程序中观察电平 |
| 外接音频设备 / 插件 | 对应硬件、系统组件与页面入口 | 按实际列出的设备和状态逐项测试 |

## 转发浏览器麦克风

1. 在 [USB 功能](./usb.md)中确认麦克风类别可用，等待电脑重新枚举。
2. 使用可信 HTTPS，允许浏览器访问需要使用的麦克风。
3. 从工具栏打开麦克风转发，在电脑中选择 BliKVM 提供的音频输入。
4. 用短录音确认方向、音量和回声，结束后关闭转发。

浏览器自动播放策略可能要求先点击页面才能播放声音。MJPEG 图像流本身不携带音频；视频录制也不能默认包含所有音频方向。耳机可减少扬声器回录造成的回声。

若菜单不存在，先确认权限、设备能力及系统组件；不要在设备上安装旧 GStreamer 音频命令来替代当前原生链路。
