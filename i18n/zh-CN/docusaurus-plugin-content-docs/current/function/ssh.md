# 设备终端与 SSH

**设置 → 高级与诊断 → SSH 终端**打开的是 BliKVM 自身管理终端，不能当作被控电脑桌面或串口。当前网页终端通过已认证的实时通道连接设备服务。

## 网页终端

1. 使用拥有设备终端权限的账号登录。
2. 打开入口，先用 `date`、`uname -a` 等只读命令确认目标环境。
3. 进行与当前镜像匹配的管理操作，结束后关闭终端并退出账号。

管理员终端能够改变设备系统。未知脚本、错误分区命令和网络配置都可能中断远程管理；网页断开也不一定使已启动的后台任务停止。

## 独立 SSH 客户端

若镜像提供 SSH 服务，可从自己的终端按实际地址、端口及操作系统账号连接：

```sh
ssh 用户名@设备地址
```

网页账号与操作系统 SSH 账号分开管理，不能认为 `admin/admin` 或旧镜像的 `blikvm/blikvm` 必然适用。SSH 主机指纹变化时，先核对是否刚重装或恢复出厂，再更新客户端信任。

需要访问被控设备的串口时，使用[串口终端](./serial-terminal.md)；不需要在旧网页配置中保存操作系统 SSH 密码。

## 原生 A/B 系统的持久化 Linux 用户

Pi4B、V4、RV1126B 从系统/App `3.0.5-dev.2026111502` 开始提供统一的原生账号
管理。先安装配套的签名**系统更新**；只更新 App 不能增加这项系统能力。以 root 执行：

```sh
adduser ops
passwd ops
```

命令会交互询问密码。随后可用 `ssh ops@BLIKVM_ADDRESS` 登录，用户自行执行
`passwd` 修改自己的密码。默认 `/home/ops` 保存在持久化 `/data/home`。
公钥登录使用标准 `/home/ops/.ssh/authorized_keys`：归 `ops` 所有，`.ssh` 权限
0700，公钥文件权限 0600。网页账号及角色与 Linux 账号独立。可能包含网页管理凭据的运行环境文件 `blikvm.env` 仅 root 可读。

需要授予完整系统管理权限时，由 root 执行：

```sh
addgroup ops wheel
```

重新以 `ops` 登录后，执行 `sudo -i` 并输入 **ops 自己的密码**。
使用 `delgroup ops wheel` 撤销角色，同时关闭此前的提权会话。
使用 `deluser ops` 删除登录账号；不主动删除时 home 会保留。保留文件尚未处理前，
避免把原 UID 分配给其他人。多 Linux 用户不另设网页管理界面。

原有 root 密码、公钥及 SSH 主机身份保留。root 仍可执行 `passwd root`；网页 SSH
改密仍只管理 root，且需要验证当前 root 密码。验证新账号时请保留可用的 root 连接。

普通 App 和配套 A/B 更新会保留自建用户、密码、组成员和 home。系统分区保持只读，
原生命令通过系统链接修改专用持久化账户文件。不要替换这些链接，也不要尝试把
SquashFS 重新挂载为可写。自定义自启服务与网页共用[系统脚本](./scripts.md)目录和执行器。

旧系统不支持新账户布局：新用户在旧系统不可用，新布局下修改的密码也不会反向同步到
旧的仅 root 存储。回到配套新系统时新数据仍保留，但这不保证降级后的凭据兼容。
恢复出厂设置会清除自建用户及 home；重新烧录前请备份数据。

系统将 `/data/work/conf` 保持为 root 所有、0700 权限。即使旧 App 在回退后重新
写出 0644 配置文件，普通 SSH 用户仍无法读取凭据。新脚本管理布局请使用配套
的系统和 App。

## 原生 A/B 系统的 Bash 终端

从系统/App `3.0.5-dev.2026111601` 开始，Pi4B、V4 和 RV1126B 的 root 与新建
Linux 用户默认使用 Bash 登录。已有普通用户保留原来选择的 shell。
`/bin/sh` 仍为 BusyBox ash，系统脚本和 POSIX 脚本继续使用它。

交互式 SSH 登录会显示型号、主机名、本次连接的设备地址、OS/App 版本及持久化
目录。root 提示符为 `user@host:目录#`，普通用户以 `$` 结尾。在启动交互式 Bash
前设置 `NO_COLOR=1`，或使用 `dumb` 终端，可关闭颜色。用户主目录的
`~/.hushlogin` 可隐藏欢迎信息。非交互式 SSH 命令及文件传输不会输出欢迎信息。
使用 `pstree -p` 可查看进程树及 PID。

root 的主目录仍是 `/root`，仅 Bash 历史保存在
`/data/work/state/shell/root/.bash_history`。普通用户使用各自持久化主目录内的
`~/.bash_history`，历史文件权限为 0600。多个会话追加历史，不互相覆盖。
RV 原有的私有 root 历史只导入一次，并保留原文件。持久化存储或主目录不可用、
路径不安全时，关闭历史持久化，不使用共用临时文件。不要在命令参数中输入密码或令牌。

新用户的 `.bashrc` 会加载共享默认配置，可在其中添加别名和个人终端设置；
已有用户的自定义启动文件保持不变。创建用户时也可使用原生命令
`adduser -s /bin/bash USER` 显式选择 Bash，无需将系统分区重新挂载为可写。
