# 更新与维护

使用管理员账号进入**设置 → 设备与系统 → 更新与维护**，再点击**打开软件更新**。选择文件前，先区分**应用升级**与**系统升级**。

[![Demo 中的更新与维护](/assets/images/software-current/updates-zh-detail.png)](/assets/images/software-current/updates-zh.png)

*Demo 截图：此处展示维护功能入口，编写本指南时没有对设备执行升级。*

## 选择正确的升级类型

| 类型 | 升级包 | 预期过程 |
| --- | --- | --- |
| 应用升级 | 兼容且已签名的 `.tar.gz` 或 `.tgz` 应用包。 | 校验并安装，随后重启应用并进行健康检查，网页可能短暂断开。 |
| 系统升级 | 在支持 A/B 升级的系统上，使用兼容且已签名的 `.raucb` 包。 | 写入非活动槽位，明确执行重启步骤，再验证启动结果、版本及健康状态。 |

使用针对当前平台和升级机制发布的包，不要解压，也不要将其他文件改扩展名后上传。旧系统的 `.deb` 或脚本安装包，不能与当前应用包、系统包混用。

## 开始前确认

- 记录当前应用版本、系统版本及界面显示的槽位信息。
- 阅读升级包的发布说明与兼容条件。
- 保持供电和网络稳定，并安排必要时的设备恢复途径。
- 完成虚拟介质写入及其他会被服务或设备重启打断的任务。
- 若界面已有升级任务，先查看它的状态，再决定是否开始新任务。

## 应用升级

1. 选择**应用升级**，选取兼容的应用包。
2. 上传后等待文件信息和校验结果。
3. 启动一次升级，通过任务状态和日志观察进展，不要反复提交同一文件。
4. 应用重启时网页可能断线，恢复连接后按需重新进入更新与维护。
5. 检查任务最终结果、当前运行的应用版本及控制台基本功能。网页重新连上，并不等于升级成功。

## 系统升级

1. 选择**系统升级**，上传兼容且已签名的 `.raucb` 包。
2. 启动升级，观察校验和安装进度。
3. 若任务显示**等待重启（staged）**，表示非活动槽位已写入；此时仍在运行原系统，还不是最终成功状态。
4. 界面提示可以重启、且已准备好中断连接时，使用维护功能重启 **BliKVM**。不要误用被控电脑的 ATX 电源操作。
5. 重新连接后，核对任务结论、当前系统版本 / 槽位和健康检查。界面显示升级成功、且任务为 committed，表示目标系统通过升级任务的检查。

## 如何判断任务结果

| 状态或结论 | 含义与下一步 |
| --- | --- |
| 校验中 / 安装中 | 任务仍在进行，保持供电。 |
| 等待重启（staged） | 系统已写入，等待执行重启步骤。 |
| 重启中 / 检查中 | 等待重启及健康检查，再查看最终结论。 |
| 升级成功（committed） | 目标版本已通过任务检查，还应确认日常功能正常。 |
| 已回退（rolled back） | 已返回原系统，不代表目标版本升级成功，应查看任务详情。 |
| 失败 / 需要检查 | 先阅读错误和诊断信息，再决定如何重试。 |

任务保存在设备端，浏览器断开本身不会取消安装，恢复连接后应回到状态页检查。上一个任务未明确结束时，不要反复上传或强制重启，应先查看状态和发布说明中的恢复步骤。

反馈问题时，请提供包名、设备型号、升级前与当前运行版本、任务状态及错误文本，分享日志前移除私有凭据。旧文档中的 `update.py`、`dpkg` 和 `kvmd-web` 命令，不属于当前网页升级流程。
