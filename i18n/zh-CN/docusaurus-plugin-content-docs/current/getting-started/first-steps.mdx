# 首次使用

先在局域网内连接 BliKVM，打开网页并确认画面、键盘和鼠标正常，再配置远程访问。

:::info 本指南的适用范围
本文介绍当前版本的 BliKVM 网页界面。实际功能取决于硬件、已安装系统和账号权限。文中截图来自[在线 demo](https://blikvm.com/demo/)，其中的电脑画面与状态均为模拟，不代表 HDMI、USB 或电源控制已经通过实机测试。
:::

## 开始前：需要先烧录系统吗？

已预装系统并能正常启动的设备可直接从下面的接线步骤开始。自行组装、空白 SD 卡或需要重装系统时，先按[烧录 SD 卡与重装系统](./flashing-os.mdx)准备启动介质；不要把给 BliKVM 烧录系统与通过虚拟介质给被控电脑安装系统混淆。

## 1. 连接硬件

1. 按对应型号的硬件指南连接电源和网线。
2. 将**被控电脑的 HDMI 输出**连接到 BliKVM 的 HDMI 输入。
3. 使用支持数据传输的 USB 线，将 BliKVM 的 **USB 设备端 / OTG 接口**连接到被控电脑。键盘、鼠标和虚拟介质通过这条连接工作，只有 HDMI 线无法控制电脑。
4. 等待设备启动完成，首次启动期间不要中断初始化。

ATX 接线为可选项，可以先不连接，验证画面和输入后再按型号接线指南添加电源控制。

## 2. 查找地址并登录

BliKVM 通常通过 DHCP 从路由器获取地址。有显示屏的设备可查看屏幕，也可以在路由器的 DHCP 客户端列表中查找。

在新版浏览器中打开设备地址，例如 `https://192.168.0.100/`，请替换成实际地址，并使用设备配置的协议。如果 HTTP 自动跳转到 HTTPS，继续使用 HTTPS 地址。私有设备出现证书提示时，应先核对设备地址和证书，再决定是否继续。

使用默认凭据的全新安装，网页用户名和密码均为 `admin`。已初始化或经过定制的设备可能不同。登录后，在**设置 → 账号与安全 → 账号、密码与双重验证**中修改密码，详见[账号与安全](./auth.mdx)。

网页账号与操作系统的 SSH 账号是两套凭据，不能直接套用网页密码或旧镜像的 SSH 默认密码。

## 3. 验证画面和输入

![BliKVM demo 控制台](/assets/images/software-current/console-zh.png)

*Demo 截图：被控电脑画面和连接状态为模拟数据。*

1. 确认控制台出现被控电脑的画面。若黑屏，先唤醒电脑，检查 HDMI 方向和输入分辨率。
2. 点击画面区域，尝试打开并关闭电脑的应用菜单等无破坏性操作。
3. 确认键盘输入和鼠标移动能够传到电脑。若有画面但无法控制，检查 USB 数据线、设备端 / OTG 接口、USB 设置及账号的输入权限。
4. 在**设置 → 视频与摄像头 → HDMI 视频 → 高级设置**中选择可用的视频模式。若提供 H.264 WebRTC，可先从该模式开始，其他选择见[视频模式](../video/video-modes.md)。

能看到真实电脑画面、发送输入，并在刷新网页后重新连接，才算基本验证完成。连接状态显示绿色，不等于 HDMI 和 USB 均正常。

## 4. 接下来可以做什么

- 通过[网页界面指南](./web-interface.md)了解工具栏和设置入口。
- 使用[虚拟介质](../peripheral-devices/msd.md)安装操作系统。
- 查看当前版本并[更新 BliKVM](../function/update.md)。
- 局域网连接正常后再配置远程访问。远程能打开网页，仍可能遇到独立的 [WebRTC 连通问题](../video/webrtc.md)。

## 连接异常时先检查什么

| 现象 | 优先检查 |
| --- | --- |
| 找不到设备地址 | 电源、网口连接和路由器 DHCP 列表；确认浏览器所在网络能够访问设备。 |
| 登录失败 | 是否为正确设备、账号密码是否正确、是否需要双重验证码。 |
| 网页正常但无画面 | 先检查电脑电源和 HDMI 信号，再排查浏览器与视频传输。 |
| 有画面但无法控制 | USB 数据连接、USB 功能开关和账号权限。 |
| 找不到菜单项 | 硬件和系统是否支持、账号角色是否允许；demo 可能展示实机没有的功能。 |
