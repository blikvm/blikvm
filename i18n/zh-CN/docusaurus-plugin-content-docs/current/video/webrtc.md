# WebRTC 连接排查

WebRTC 通过协商后的媒体连接传输视频。能够打开 BliKVM 网页，只能证明网页连接正常，不能证明媒体连接一定能够建立。

在**设置 → 视频与摄像头 → HDMI 视频 → 高级设置**中选择可用的 WebRTC 模式。浏览器和编码要求见[视频模式](./video-modes.md)。

## 按顺序定位

1. **先验证局域网采集。** 在局域网连接，确认电脑输出受支持的 HDMI 信号。若提供 MJPEG，可与 WebRTC 对比。
2. **检查浏览器。** 使用新版浏览器，确认所选编码受支持；只有同时提供 H.264 和 H.265 时才进行两者对比。缺少解码能力与 ICE 网络失败是不同问题。
3. **比较局域网和远程结果。** 若局域网正常、远程 WebRTC 失败，检查 NAT、防火墙、VPN 路由和媒体服务配置。仅代理 HTTPS 网页，不一定能转发协商后的媒体流量。
4. **核对媒体服务公布的地址。** 设备同时有网线、Wi-Fi 或 VPN 地址时，浏览器必须能到达媒体服务提供的地址。检查当前服务配置及连接诊断，不要修改旧版 Janus 配置路径。
5. **检查 ICE 穿透条件。** STUN 用于帮助发现地址，不负责中继媒体。TURN 中继需要部署环境单独支持并配置，不能认为设置一个公共 STUN 服务器就能适配所有网络。

## 在网页中配置 STUN / TURN

仍在 **HDMI 视频 → 高级设置**中，找到 **WebRTC 网络**区域：

1. 先关闭需要编辑的 STUN / TURN 开关；启用时，相应输入框是只读的。
2. 在 STUN 区域按一行一个填写可访问的服务器 URL，再启用 NAT 穿透（STUN）。
3. 若需要中继且已有可用 TURN 服务，先填写服务方提供的 URL、用户名和密码，按需添加其他服务器，再启用 TURN。
4. 切换开关会校验并保存配置。确认出现保存成功提示，再重新连接视频验证；仅填写输入框不会完成保存。

STUN URL 使用 `stun:主机:端口` 格式；TURN URL 使用 `turn:主机:端口` 或 `turns:主机:端口`。请使用你的服务方提供的值，不要将占位符直接保存。配置中继不能代替 HDMI 信号检查，也不应在未确认当前网络条件时随意开放端口。

## 反馈问题时提供哪些信息

请提供应用和系统版本、设备型号、浏览器及操作系统、所选模式、局域网与远程测试结果，以及界面显示的连接错误。分享诊断信息前移除密码、令牌和私有配置。

当前实现已不再使用旧指南中的 Janus 路径及 `kvmd-web` 重启流程，请不要将那些命令复制到当前系统。临时对比时，先切换另一种可用模式，不必同时修改无关网络设置。
