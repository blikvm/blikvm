# Repository instructions

## GitHub Releases

When drafting or editing release notes, follow `releases/README.md` and use `releases/TEMPLATE.md`. Store each reviewed version in `releases/<tag>.md`. Keep the English and Chinese sections equivalent, verify links against actual release assets, and use `scripts/release-notes.mjs` to validate before updating a release body. Do not invent validation results or change release tags, assets, or publication status without user authorization. These rules apply to release tasks; retain the existing website/documentation conventions for other tasks.
