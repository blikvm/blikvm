BliKVM v4 is a production-ready, plug and play KVM-over-IP device that offers professional users a convenient solution **for remote server or workstation management**. It runs a Linux-based system. With BliKVM, you can easily **power on/off, restart your computer, configure UEFI/BIOS settings, and perform OS reinstallation using an emulated Mass Storage Device**. BliKVM simulates a keyboard, mouse, and monitor, all accessible through a web browser, ensuring a seamless user experience. **Its hardware-level access guarantees independence from specific remote ports, protocols, or services**, making it a highly flexible and reliable remote management solution for professionals!

## **Installation Requirements**

:::tip "In addition to the v4 kit, you will need the following equipment:"
    - Power adapter (5V 3A, USB-C port, or 12V 2A DC port). If you plan to use PoE (Power over Ethernet) or if the USB ports on your controlled computers provide sufficient power, a separate power adapter is not required.
    - The measured power consumption of the v4 is around 4 watts when using the loop-out and single web access.
    - HDMI cables (at least one). If you also need to use the HDMI loop-out interface, you will need two cables.
    - Ethernet cable(s) (provide based on your requirements). One cable is required for using the ATX power switch function, and one cable is required for using the Ethernet connection.
    - USB-C to USB-A cable (for mouse and keyboard data transmission).
:::


:::warning "Solution for v4 Power Supply Issues"
    The v4 is designed to support multiple power input methods simultaneously, such as the 5V port, USB-PC port, 12V port, and PoE port. When multiple power sources are connected, the v4 will select the port with the highest voltage for power supply. This may result in the controlled PC powering the v4. Since many PCs have limited USB power supply capabilities, you might notice that the v4 is affected when the controlled PC is powered on or off. To prevent this issue, you need to add a [USB splitter board](/docs/accessories/usb-splitter-guide) to the USB port.
:::

## Front-panel LCD and BUTTON 1 / BUTTON 2 {#front-panel}

v4 has a 1.33-inch color **LCD** showing BliKVM status, not the computer's HDMI picture. Other models commonly use OLED and do not share these button controls.

Face the front panel and use the **SW1 / SW2** enclosure markings:

| Button | Position | Normal short press |
| --- | --- | --- |
| BUTTON 1 | Lower, SW1 | Toggle backlight; this does not shut down BliKVM or the computer |
| BUTTON 2 | Upper, SW2 | Change page; wake the display when dark |
| Both | Hold BUTTON 1 + BUTTON 2 for about 3 seconds | Enter / exit Wi-Fi provisioning on images containing the newer service |

The newer service executes short actions on release. A combined hold suppresses individual actions. Releasing either button before 3 seconds cancels the provisioning countdown.

### Display pages

- **Overview:** address, temperature, load, memory, uptime and access QR code.
- **Network:** hostname, interfaces and addresses, including VPN. Multiple interfaces rotate through subpages.
- **System:** temperature, CPU / memory, total SD capacity, free data-partition space, app / OS versions and active slot.
- **Branding:** startup, wake and page-cycle branding. Idle returns to overview.

## Wi-Fi provisioning without Ethernet {#wifi-setup}

:::info Image requirements
This procedure requires the newer v4 display provisioning service, NetworkManager and a matching wireless driver. Updating only the web app on an older image may not provide it. If provisioning does not appear, connect Ethernet and use [web Wi-Fi settings](../network/wifi.md), then check the installed image's feature notes.
:::

1. Attach the Wi-Fi antenna and stable power. Hold **BUTTON 1 + BUTTON 2 together for about 3 seconds** until the countdown and hotspot page appear.
2. On your phone, join the temporary **`BliKVM-xxxx`** hotspot shown on the LCD. Scan its Wi-Fi QR code or enter the displayed SSID and password manually. **A new password is generated each time**; illustration passwords do not work on real devices.
3. Stay connected if the phone warns of no Internet. If the setup page does not open automatically, browse to **`http://192.168.4.1`**. This is a provisioning address, not the final KVM management address.
4. Choose your home / office Wi-Fi, enter its password and connect. Hidden networks support manual SSID entry. Rescanning may briefly disconnect the phone; reconnect as directed.
5. The hotspot stops while BliKVM joins the target network, so phone disconnection is expected. On success, the LCD shows the new IP for about 5 seconds, then returns to overview.
6. Join the same target network with the management computer or phone. Open the LCD's management address and verify page, video and input. Stop using `192.168.4.1` after provisioning.

### Failure, exit and recovery

- On connection failure, provisioning restores the hotspot. Check its current SSID / password on the LCD, reconnect and verify target credentials and signal.
- Choose **Close hotspot and exit**, or hold both buttons again for about 3 seconds, to exit. If connection was incomplete, the service attempts to restore the previous wireless connection.
- About 10 minutes without provisioning activity exits the hotspot. Automatic status refresh does not count as new activity.
- Provisioning temporarily interrupts existing Wi-Fi. Retain Ethernet if continuous management is needed. The setup hotspot does not share Internet access.
- For no hotspot, check the display state, antenna, image version and driver rather than guessing a fixed factory password.

## **Serial Console Access via the 5V Port**

The 5V port can be used both for power supply and serial console access at the same time. The default baud rate is 115200. There is an onboard CH341-based USB to UART converter present inside BliKVM v4 which is connected to UART0 of the [mCore-H616 SoC](https://linux-sunxi.org/H616), so you can connect a USB port of a PC to the 5V port without an external UART and a USB-C to dupont adapter.

:::warning "PC USB port current output"
    Be careful when trying to use the 5V port because a PC USB port alone may not be able to provide 3A (5V) which is a documented requirement for the board to work. Either use a 12V 2A DC port at the same time as using the 5V port for serial communication without a [USB Splitter](/docs/accessories/usb-splitter-guide) board, or use the splitter board to split out the VCC pin and use a separate 5V 3A power supply to provide power to the 5V port's VCC pin. Likewise, when disconnecting a cable from the 12V 2A DC port while BliKVM is powered on, make sure to disconnect the cable from the 5V port first (because that will become the power source for BliKVM v4 after the 12V 2A source is disconnected unless a splitter is used).

You should see something like this in your host kernel log (if you are using a Linux-based OS) when attaching a USB cable to the 5V port of BliKVM v4:
    ```
    usb 1-1.2: new full-speed USB device number 12 using xhci_hcd
    usb 1-1.2: New USB device found, idVendor=1a86, idProduct=7523, bcdDevice=81.34
    usb 1-1.2: New USB device strings: Mfr=0, Product=2, SerialNumber=0
    usb 1-1.2: Product: USB Serial
    ch341 1-1.2:1.0: ch341-uart converter detected
    usb 1-1.2: ch341-uart converter now attached to ttyUSB0
    ```

Accessing this port can then be done using [GNU screen](https://www.gnu.org/software/screen/) or [TIO](https://github.com/tio/tio):
    ```
    tio /dev/ttyUSB0
    mangopimcore login: blikvm
    # ...
    ```

If you need to check how much data is received over UART0 you can do this by looking at the counters exposed via proc as follows (the rx counter should increase when the data is sent from an external host if the built-in USB to UART converter is working properly):
    ```
    root@mangopimcore:~# grep '0: uart' /proc/tty/driver/serial
    0: uart:16550A mmio:0x05000000 irq:284 tx:20306 rx:40 pe:1 RTS|DTR
    ```
